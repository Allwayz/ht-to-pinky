# HomeTrans 用例到 Pinky 用例

## 保留什么

从每条 `### Scenario` 只取标题、动作、预期结果、测试点。

丢掉编号映射表、场景来源映射、优先级、`[推导]`、`已安装`、`AutoTest 自动处理`。这些不是屏幕操作。

## 一条怎么处理

按下面的顺序判断。先命中的规则生效。

| 情况 | 结果 |
|---|---|
| 标题含 `[SKIP]`，或脚本标了 `skip` | 未转换。原因写 SKIP 原文 |
| 脚本标了 `camera` | 未转换。不写出点击二维码、允许相机、开手电筒的步骤 |
| 脚本标了 `deletion` | 未转换。不写出删除账号、注销账号或删除内容的步骤 |
| 脚本标了 `not_a_screen_action`，或动作是在构造、注入、让页面返回某段数据 | 未转换。Pinky 不能制造应用内部数据 |
| 预期要进入登录后的页面，而前置条件没有给出可用账号 | 未转换 |
| 脚本标了 `vague_control`，且用户没有给出这个动作的控件对照 | 未转换。不要把「继续」猜成某个箭头或按钮 |
| 脚本标了 `measurement` | 删掉高度、省略号、滚动、像素、单行这些测试点。还剩下可见原文就转换；一个不剩就未转换 |
| 其余 | 转换成一条用例 |

测量类测试点删掉后，如果还要求「没有某句提示」或「输入的字符还在」，就只保留这两类。写成 Pinky 去读文字，并写明不要求测量高度、省略号或滚动。

同一个文件里，若后一条用例用了相同动作并写了「等待检查结束」，它的通过条件用最终那句原文。前一条单独出现的过渡文案要写明不能当成通过。

只检查控件是否存在的用例，不要在步骤里填写或提交，除非动作本身写了输入什么。

## 动作怎么改

把 ` -> ` 拆成编号步骤。每步只做一种事：打开应用、点一个带「」的可见文字、输入一段原文、向指定方向滑动、等待一句原文、返回。

- `打开 X`：用户给了包名就写包名，否则写应用名。不要改成点桌面上的「继续」。
- `点击「Log in」`：写成点「Log in」。书名号里的字原样保留。
- `输入「https://example.invalid」`：原样输入这串字。
- `输入 300 个字符「a」`：写明个数和字符，不要改成长度或换成别的样本。
- `不输入地址`：确认对应输入框是空的；框里有旧文字就先清空。
- `向左滑动三次`：写明在哪个区域滑、滑几次。源文件没写区域时，用动作里已有的区域名称，不要另编页面。
- `任意一屏`、`某个页面` 这种没有具体对象的步骤，改成打开后当前所在的那一屏，并写明就是这一屏。
- 每条用例都从它自己的第一步开始。上一条停在别的页面时，只按本条动作里写过的返回或重新打开来恢复，不要补一条源文件没有的业务路径。

用户给了控件对照时，只替换对照表里写明的那一个动作，不影响别的步骤。

## 通过条件

只写屏幕上能读到的原文，或原文明确不出现。

- 保留预期和测试点里的「」原文。
- `仍可看到输入框` 改成：该输入框还在；如果本条刚输入过文字，框里仍然是那串字。
- 加载中、正在检查这类一闪而过的状态，不单独作为通过，除非这条用例的全部预期就是它，且同文件没有另一条把最终结果分开。
- 浏览器用例只断言地址栏里源文件写出的地址片段，以及是否离开了原应用。离开应用可能要用户允许，步骤里说明即可。

## 输出模板

```markdown
# Pinky 测试用例

由 HomeTrans 的 test_case.md 改写。一次只把下面的一条用例交给 Pinky，不要把整份文件丢进去。

应用：<名称或未提供>
包名：<包名或未提供>
设备：<设备或未提供>
界面语言：<语言或未提供>

<仅当存在相机类未转换用例时写：不要点二维码或相机入口，不要允许相机权限。>
不要删除账号，不要注销账号，不要删除内容。

## 用例 1：<场景标题>
来源：`<test_case.md 路径>` Scenario <N-M>

1. <一步>
2. <一步>
通过：<能看见或不能看见的原文>
不要：<本条额外禁止；没有就不写这一行>

## 未转换

| 来源 | 原因 |
|---|---|
| `<路径>` Scenario <N-M> | <一句话> |
```

用例编号按源文件路径排序，文件内按 Scenario 出现顺序。未转换表用同一顺序。两组合起来必须正好等于全部 Scenario。
